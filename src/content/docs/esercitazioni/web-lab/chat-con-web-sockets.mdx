Ecco un'esercitazione pratica e completa
per creare una **mini chat / bacheca in tempo reale**
con [**WebSocket**](https://it.wikipedia.org/wiki/WebSocket) e **Node.js**,
usando la libreria leggera `ws` e una pagina [**HTML**](https://it.wikipedia.org/wiki/HTML)/[**JavaScript**](https://it.wikipedia.org/wiki/JavaScript) nativa (senza framework aggiuntivi).

A differenza di una classica richiesta [**HTTP**](https://it.wikipedia.org/wiki/Hypertext_Transfer_Protocol) (dove il client chiede e il server risponde una sola volta), un **WebSocket** apre una **connessione persistente e bidirezionale**: sia il server sia i client connessi possono inviare messaggi in qualsiasi momento.

<AsideTip title="Come nasce la connessione: Upgrade HTTP sopra TCP">
La connessione inizia su un normale socket [**TCP**](https://it.wikipedia.org/wiki/Transmission_Control_Protocol): il client invia una richiesta **HTTP/1.1 `GET`** con gli header `Upgrade: websocket` e `Connection: Upgrade` (insieme a `Sec-WebSocket-Key` per l'handshake). Se il server supporta WebSocket, risponde con **`101 Switching Protocols`** e `Upgrade: websocket`: da quel momento la stessa connessione TCP resta aperta e viene riutilizzata per scambiare frame WebSocket bidirezionali, senza ripetere l'overhead HTTP a ogni messaggio.
</AsideTip>

**Architettura dell'esercitazione**
- **Server** (`server.js`): avvia un server WebSocket sulla porta `8080`, ascolta gli eventi `connection`, `message` e `close`, e inoltra (**broadcast**) ogni messaggio ricevuto a tutti i client attualmente connessi.

- **Client** (`index.html`): si connette a `ws://localhost:8080`, mostra lo stato della connessione, invia i messaggi digitati e aggiorna la lista in tempo reale all'arrivo di nuovi messaggi.

## Introduzione

<ExpectedResults>
- il server WebSocket viene avviato in [Node.js](https://it.wikipedia.org/wiki/Node.js) sulla porta `8080` tramite la libreria `ws`;

- l'invio di un messaggio da un client viene inoltrato in broadcast a tutti i client connessi con relativo timestamp;
- il client aggiorna lo stato della connessione (`open`, `close`, `error`) e gestisce la disconnessione in modo sicuro.
</ExpectedResults>

3. ### Scrivi il server WebSocket (server.js):
    
    Crea il file server.js con il codice seguente. 
    
    Ogni nuovo client entra in wss.clients, così il server può inviare il messaggio a tutti gli utenti attivi.  
      
    Il file `server.js` crea un **server WebSocket** in Node.js sulla porta `8080` usando la libreria `ws` e inoltra in **broadcast** i messaggi ricevuti a tutti i client connessi.

    Ecco come funziona passo passo:

    ##### 3.1. Importazione e avvio del server

    * `import { WebSocketServer, WebSocket } from 'ws';` importa la classe per creare il server WebSocket e le costanti/tipi della libreria `ws`.
    * `const PORT = 8080;` imposta la porta su cui il server resta in ascolto.
    * `const wss = new WebSocketServer({ port: PORT });` avvia il server WebSocket sulla porta `8080` e stampa un messaggio di conferma in console.

    ```javascript title="server.js"
    import { WebSocketServer, WebSocket } from 'ws';

    const PORT = 8080;
    const wss = new WebSocketServer({ port: PORT });

    console.log(`Server WebSocket in ascolto su ws://localhost:${PORT}`);
    ```

    ##### 3.2. Gestione di una nuova connessione (`connection`)

    Ogni volta che un client (ad esempio una scheda del browser che apre `index.html`) si collega a `ws://localhost:8080`, scatta `wss.on('connection', (socket, req) => { ... })`:

    * `req.socket.remoteAddress` recupera l'indirizzo del client e `wss.clients.size` indica quanti client sono attivi in quel momento.
    * `socket.send(...)` invia **solo a quel client** un messaggio JSON con `type: 'system'` per confermare che la connessione è attiva.

    ```javascript title="server.js"
    /* ...  */

    wss.on('connection', (socket, req) => {
        const clientIp = req.socket.remoteAddress;
        console.log(`Nuovo client connesso (${clientIp}). Client attivi: ${wss.clients.size}`);

        socket.send(
            JSON.stringify({
                type: 'system',
                text: 'Connessione WebSocket stabilita con il server.'
            })
        );
    ```

    ##### 3.3. Ricezione e inoltro in broadcast (`message`)

    Quando un client invia dati, si attiva `socket.on('message', (rawData) => { ... })`:

    * `rawData.toString().trim()` converte i dati ricevuti in testo e rimuove gli spazi superflui; se il messaggio è vuoto (`!messageText`), viene ignorato.
    * Viene costruito un oggetto JSON (`payload`) con:
    * `type: 'chat'` per distinguerlo dai messaggi di sistema;
    * `text` con il testo del messaggio;
    * `timestamp` con l'ora locale (`it-IT`).
    * Il ciclo `for (const client of wss.clients)` scorre tutti i client collegati e invia il `payload` solo a quelli con `client.readyState === WebSocket.OPEN` (connessione effettivamente aperta).

    ```javascript title="server.js"
    /* ...  */

        socket.on('message', (rawData) => {
            const messageText = rawData.toString().trim();
            if (!messageText) return;

            console.log(`Messaggio ricevuto: ${messageText}`);

            const payload = JSON.stringify({
                type: 'chat',
                text: messageText,
                timestamp: new Date().toLocaleTimeString('it-IT')
            });

            for (const client of wss.clients) {
                if (client.readyState === WebSocket.OPEN) {
                    client.send(payload);
                }
            }
        });
    ```

    ##### 3.4. Chiusura ed errori (`close` ed `error`)

    * `socket.on('close', ...)` scatta quando un client chiude la scheda o perde la connessione e aggiorna in console il numero di client attivi.
    * `socket.on('error', ...)` intercetta eventuali errori sul singolo socket evitando che il server si blocchi per un problema su una connessione.

    ```javascript title="server.js"
    /* ...  */

        socket.on('close', () => {
            console.log(`Client disconnesso. Client attivi: ${wss.clients.size}`);
        });

        socket.on('error', (err) => {
            console.error('Errore sul socket:', err.message);
        });
    });
    ```

    ##### 4.3. Struttura della pagina (`<body>`)
    Crea l'interfaccia minima dell'applicazione: il titolo, il riquadro #status per lo stato della connessione, il contenitore #messages dove compariranno i messaggi e il form #chat-form con casella di testo e pulsante Invia (inizialmente disabilitato finché il WebSocket non è connesso).
    
    ```html title"index.html"
        <body>

            <h1>Bacheca Real-Time (WebSocket)</h1>
            <div id="status">Stato: connessione in corso...</div>
            <div id="messages"></div>

            <form id="chat-form">
                <input id="msg-input" type="text" placeholder="Scrivi un messaggio..." autocomplete="off" required />
                <button id="send-btn" type="submit" disabled>Invia</button>
            </form>
    ```

    ##### 4.4. Script — Riferimenti al DOM, connessione WebSocket e funzione di rendering
    Recupera gli elementi chiave della pagina, apre la connessione verso ws://localhost:8080 tramite l'API nativa WebSocket e definisce appendMessage() per aggiungere un elemento al contenitore e far scorrere automaticamente verso il basso la chat
    ```html title"index.html"

            <script>
                const statusEl = document.getElementById('status');
                const messagesEl = document.getElementById('messages');
                const formEl = document.getElementById('chat-form');
                const inputEl = document.getElementById('msg-input');
                const sendBtn = document.getElementById('send-btn');

                const socket = new WebSocket('ws://localhost:8080');

                function appendMessage(htmlContent, isSystem = false) {
                    const div = document.createElement('div');
                    div.className = isSystem ? 'msg sys' : 'msg';
                    div.innerHTML = htmlContent;
                    messagesEl.appendChild(div);
                    messagesEl.scrollTop = messagesEl.scrollHeight;
                }
    ```
    ##### 4.5. Script — Gestione degli eventi del socket (open, message, close, error)
    Reagisce ai cambiamenti del canale WebSocket: abilita il pulsante all'apertura (open), decodifica il JSON ricevuto dal server e lo stampa a video (message), disabilita l'invio alla chiusura (close) e segnala eventuali anomalie (error).
    
    ```html title"index.html"

                socket.addEventListener('open', () => {
                    statusEl.textContent = 'Stato: connesso a ws://localhost:8080';
                    sendBtn.disabled = false;
                });

                socket.addEventListener('message', (event) => {
                    const data = JSON.parse(event.data);
                    if (data.type === 'system') {
                        appendMessage(data.text, true);
                        return;
                    }
                    appendMessage(`<strong>[${data.timestamp}]</strong> ${escapeHtml(data.text)}`);
                });

                socket.addEventListener('close', () => {
                    statusEl.textContent = 'Stato: disconnesso dal server';
                    sendBtn.disabled = true;
                });

                socket.addEventListener('error', () => {
                    statusEl.textContent = 'Stato: errore di connessione';
                });
    ```
    ##### 4.6. Script — Invio del form, sanitizzazione (escapeHtml) e chiusura del documento
    Intercetta l'invio del form impedendo il ricaricamento della pagina, verifica che il testo non sia vuoto e che il socket sia in stato WebSocket.OPEN, invia il messaggio e svuota l'input; escapeHtml() neutralizza i caratteri speciali prima di inserirli nell'HTML, poi si chiudono script e body.

    ```html title"index.html"

                formEl.addEventListener('submit', (event) => {
                    event.preventDefault();
                    const text = inputEl.value.trim();
                    if (!text || socket.readyState !== WebSocket.OPEN) return;

                    socket.send(text);
                    inputEl.value = '';
                    inputEl.focus();
                });

                function escapeHtml(str) {
                    return str
                        .replaceAll('&', '&amp;')
                        .replaceAll('<', '&lt;')
                        .replaceAll('>', '&gt;')
                        .replaceAll('"', '&quot;');
                }
            </script>
        </body>
    </html>
    ```

## Riepilogo

<KeyConcepts>
- [WebSocket](https://developer.mozilla.org/it/docs/Web/API/WebSockets_API): protocollo di comunicazione bidirezionale e persistente tra client e server su un'unica connessione.
- [Node.js](https://it.wikipedia.org/wiki/Node.js): ambiente di esecuzione JavaScript lato server usato qui per ospitare il server WebSocket.
- `WebSocketServer` (`ws`): classe della libreria `ws` che ascolta le connessioni in ingresso e gestisce `wss.clients`.
- `broadcast`: invio di un messaggio ricevuto da un client a tutti gli altri client attualmente connessi e aperti.
- `readyState` (`WebSocket.OPEN`): proprietà che indica lo stato attuale della connessione prima di inviare dati con `send()`.
- Eventi `connection`, `open`, `message`, `close` ed `error`: gestori che permettono di reagire all'apertura, allo scambio dati, alla chiusura o agli errori del socket.
- [JSON](https://it.wikipedia.org/wiki/JSON): formato testuale usato per strutturare messaggi di sistema e di chat (`type`, `text`, `timestamp`).
- [DOM](https://it.wikipedia.org/wiki/Document_Object_Model): struttura della pagina HTML aggiornata dinamicamente al ricevimento dei nuovi messaggi.
</KeyConcepts>
