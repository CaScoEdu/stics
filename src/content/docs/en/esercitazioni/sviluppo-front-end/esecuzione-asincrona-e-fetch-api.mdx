### 🎯 Lesson Objective

- In this lesson, we will learn to distinguish synchronous execution from asynchronous execution and understand why some operations require a non-blocking approach.
- We will create a minimal HTML page that uses `async`, `await`, and the `Fetch API` to retrieve a text file from a server and display the result in the DOM.
- The final output is a small example that handles both successful requests and possible network errors or missing files.

<Aside type="note" title="Expected Result">
At the end of the lesson, you will have an application that:
- Requests the contents of `hello.txt` from the server using `fetch()`;
- Uses `async` and `await` to wait for the response and read the text;
- Checks the result with `response.ok` and displays it in the DOM;
- Intercepts errors with `try/catch` and communicates them to the user.
</Aside>

</StepCard>

### Coding

Below is the contents of the two files:

<Tabs>

<TabItem label="index.html" icon="seti:html" >
```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Intro Async Fetch</title>
</head>
<body>

    <button onclick="caricaMessaggio()">Load "Hello World"</button>

    <!-- Minimal container where the text will be displayed -->
    <div id="output">Waiting for a click...</div>

    <script>
    // 1. 'async' makes the function asynchronous
    async function caricaMessaggio() {
        const output = document.getElementById('output');

        try {
        // 2. 'await fetch' downloads the resource without blocking
        const response = await fetch('hello.txt');

        // 3. Check whether the file was found (e.g. 200 OK)
        if (!response.ok) {
            throw new Error('File not found!');
        }

        // 4. 'await' waits for the response body to be converted to text
        const testo = await response.text();

        // 5. Insert the text into the DOM (without using alert)
        output.textContent = testo;

        } catch (errore) {
        // Handle network problems or missing files
        output.textContent = 'Error: ' + errore.message;
        }
    }
    </script>

</body>
</html>
```
</TabItem>
<TabItem label="hello.txt" icon="document">
```txt
Hello World!
```
</TabItem>
</Tabs>

In summary, the code uses `async` and `await` to make the request non-blocking:
- `fetch('hello.txt')` starts an [HTTP](https://en.wikipedia.org/wiki/HTTP) request;
- `response.ok` verifies that the response was successful;
- `response.text()` reads the file contents as text.
- The `try/catch` block handles network errors or missing files, preventing the page from freezing and allowing the [DOM](https://en.wikipedia.org/wiki/Document_Object_Model) to be updated with the result.
</StepCard>

<Aside type="note" title="Key Concepts Summary" icon="puzzle">
- [Asynchronous execution](https://en.wikipedia.org/wiki/Asynchronous_I/O): allows operations such as network requests to wait without blocking the interface.
- [Promise](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise): represents the future result of an asynchronous operation.
- `async` and `await`: simplify Promise handling; `await` waits for a result without blocking the browser.
- [Fetch API](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API): enables network requests and receiving a `Response`.
- [HTTP](https://en.wikipedia.org/wiki/Hypertext_Transfer_Protocol): the protocol used for communication between browsers and servers.
- `response.ok`: indicates whether the HTTP response status is between 200 and 299.
- `response.text()`: reads the response body and returns it as text.
- [DOM](https://en.wikipedia.org/wiki/Document_Object_Model): the page representation that JavaScript can update.
- `try/catch`: handles errors that occur during the request or while reading the response.
</Aside>
