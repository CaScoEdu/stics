## The essential code <code>index.html</code>
In this exercise we introduce the concept of [**asynchronous execution**](https://en.wikipedia.org/wiki/Asynchronous_programming) and the use of the [**Fetch API**](https://en.wikipedia.org/wiki/Fetch_API) with the simplest possible code. On button click, the page retrieves the content of `hello.txt` and displays it without blocking the interface. To follow the example, create `index.html` and `hello.txt` in the same folder: we will see the essential flow of `fetch()` and `await`, without adding unnecessary functionality.


<Tabs>

<TabItem label="index.html" icon="seti:html" >
```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Intro Async Fetch</title>
</head>
<body>

    <button onclick="caricaMessaggio()">Load "Hello World"</button>

    <!-- Minimal container where the text is printed -->
    <div id="output">Waiting for click...</div>

    <script>
    // 1. 'async' makes the function asynchronous
    async function caricaMessaggio() {
        const output = document.getElementById('output');

        try {
        // 2. 'await fetch' downloads the resource without blocking
        const response = await fetch('hello.txt');

        // 3. Check whether the file was found (e.g. 200 OK)
        if (!response.ok) {
            throw new Error('File not found!');
        }

        // 4. 'await' waits for the response body to be converted to text
        const testo = await response.text();

        // 5. We insert the text into the DOM (without alert)
        output.textContent = testo;

        } catch (errore) {
        // Handle possible network issues or missing files
        output.textContent = 'Error: ' + errore.message;
        }
    }
    </script>

</body>
</html>
```
</TabItem>
<TabItem label="hello.txt" icon="document">
```txt
Hello World!
```
</TabItem>
</Tabs>

In short, the code uses `async` and `await` to make the request non-blocking: `fetch('hello.txt')` starts an [HTTP](https://en.wikipedia.org/wiki/Hypertext_Transfer_Protocol) request, `response.ok` checks whether the response succeeded, and `response.text()` reads the file content as text. The `try/catch` block handles network errors or missing files, preventing the page from freezing and allowing the [DOM](https://en.wikipedia.org/wiki/Document_Object_Model) to be updated with the result.

<Aside type="note" title="Key concepts summary" icon="puzzle">
- [Asynchronous execution](https://en.wikipedia.org/wiki/Asynchronous_programming): allows waiting for operations such as a network request without blocking the interface.
- [Promise](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise): represents the future result of an asynchronous operation.
- `async` and `await`: simplify Promise management; `await` waits for a result without blocking the browser.
- [Fetch API](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API): allows you to make network requests and receive a `Response`.
- [HTTP](https://en.wikipedia.org/wiki/Hypertext_Transfer_Protocol): protocol used for communication between browser and server.
- `response.ok`: indicates whether the HTTP response has a status between 200 and 299.
- `response.text()`: reads the response body and returns it as text.
- [DOM](https://en.wikipedia.org/wiki/Document_Object_Model): representation of the page that JavaScript can update.
- `try/catch`: allows you to handle errors that occur during the request or while reading the response.
</Aside>
