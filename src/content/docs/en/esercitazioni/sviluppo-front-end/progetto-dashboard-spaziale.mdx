## 🧱 The [HTML](https://en.wikipedia.org/wiki/HTML) Structure (`index.html`)

Let's start by creating the user interface.
[HTML](https://en.wikipedia.org/wiki/HTML) defines the control buttons and the console panel
where the download status and log text will appear.

```html
//index.html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Ares-IV Mission - Flight Log</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <h1>🚀 Ares-IV Mission: Flight Log</h1>
  <p>Select a log to download from the central server:</p>
  
  <!-- Control buttons -->
  <button id="btn-log1">Day 1 Log</button>
  <button id="btn-log2">Day 42 Log</button>
  <button id="btn-errore">Error Test (404)</button>

  <!-- Display console -->
  <div class="console">
    <strong>Connection Status:</strong> <span id="stato">Waiting...</span>
    <hr>
    <div id="log">No data loaded.</div>
  </div>

  <script src="app.js"></script>
</body>
</html>
```

### HTML Explanation
Each of the three buttons has a unique ID so JavaScript events can be attached to it in code.
- <code>#stato</code> will display loading progress messages (e.g., "In progress...", "Done", "Error").
- <code>#log</code> will contain the text downloaded from the text file.

## ⚙️ The [JavaScript](https://en.wikipedia.org/wiki/JavaScript) Logic (<code>app.js</code>)
Let's build the script logic by dividing it into conceptual sections.

### Snippet A: Declaring the Asynchronous Function
```javascript
// Use the 'async' keyword to enable the use of 'await' inside the function
async function loadLog(fileName) {
const elementoStato = document.getElementById('stato');
const elementoLog = document.getElementById('log');
// Codice di caricamento...
}
```
:::tip[Explanation]
The `async` keyword tells the browser that this function will perform asynchronous operations and return a `Promise`.
:::

---

### Snippet B: The HTTP Request with `await fetch()`
```javascript
// 1. Start the error-handling block
try {
    elementoStato.textContent = `Downloading ${fileName}...`;
    
    // 2. Send the request and WAIT for the response headers
    const response = await fetch(fileName);
    
    // 3. Check whether the file exists on the server (e.g., HTTP 200 OK)
    if (!response.ok) {
    throw new Error(`File not found (HTTP status: ${response.status})`);
    }
}
```
:::tip[Explanation]
`await fetch()` pauses execution inside the function until the server responds, without blocking the web page.
If the file does not exist (e.g., `404`), `response.ok` will be `false`, and we manually throw an error with `throw`.
:::

---
### Snippet C: Converting to Text and Updating the DOM
```javascript
// 4. WAIT for the entire file content to be read as text
    const testo = await response.text();
    
    // 5. Update the interface with the received data
    elementoStato.textContent = 'Connection completed successfully.';
    elementoLog.textContent = testo;
    
  } catch (errore) {
    // Handle network problems or a missing file
    elementoStato.textContent = 'TRANSMISSION ERROR!';
    elementoLog.textContent = errore.message;
  }
}
```
:::tip[Explanation]
`await response.text()` is needed because the response body arrives as a stream.
A second `await` is required to finish reading the text.
:::

---

### Snippet D: Attaching Event Listeners to the Buttons

```javascript
// Connect the function to the interface buttons
document.getElementById('btn-log1').addEventListener('click', () => loadLog('log1.txt'));
document.getElementById('btn-log2').addEventListener('click', () => loadLog('log2.txt'));
document.getElementById('btn-errore').addEventListener('click', () => loadLog('log-missing.txt'));
```

:::caution[Beware of `CORS` blocking (`Live Server`)]
Reference: [`CORS`](https://en.wikipedia.org/wiki/Cross-origin_resource_sharing).

the browser will block `fetch` for security reasons.
Remember to run the project through a local server

:::

<Aside type="note" title="Key Concepts Summary" icon="puzzle">
- [Asynchronous execution](https://en.wikipedia.org/wiki/Asynchronous_programming): lets the dashboard wait for logs to load without blocking.
- [Promise](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise): represents the future result of a request for a log file.
- `async` and `await`: allow `loadLog(fileName)` to wait for the response and for the log to be read.
- [Fetch API](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API): retrieves `log1.txt` and `log2.txt` from the server.
- [HTTP](https://en.wikipedia.org/wiki/HTTP): the protocol used to communicate with the local server.
- `response.ok`: identifies an unsuccessful HTTP response, such as the test button's `404` error.
- `response.text()`: reads the received log content and returns it as text.
- [DOM](https://en.wikipedia.org/wiki/Document_Object_Model): lets you update `#stato` and `#log` with the result and content of the load.
- `try/catch`: handles network errors or unavailable files and displays the message in the dashboard console.
</Aside>
