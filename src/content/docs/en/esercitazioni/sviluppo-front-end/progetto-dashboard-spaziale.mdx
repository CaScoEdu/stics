## 📋 Requirements analysis

### 🎯 Lesson objective

- In this lesson, we will learn to distinguish synchronous execution from asynchronous execution and understand why some operations require a non-blocking approach.
- We will create a space mission dashboard with HTML, CSS, and JavaScript, using `async`, `await`, and the Fetch API to retrieve flight logs from the server.
- The application will handle both successful log loading and possible network errors or missing files.

<Aside type="note" title="Expected result">
At the end of the lesson, you will have a space dashboard where:
- the user can choose which flight log to download;
- the content is requested from the server with `fetch()`;
- waiting for the response and reading the text are handled with `async` and `await`;
- the result is checked through `response.ok` and displayed in the DOM;
- errors are intercepted with `try/catch` and reported to the user.
</Aside>

```html
//index.html
<!DOCTYPE html>
<html lang="en">

  <link rel="stylesheet" href="style.css">
```

#### HTML explanation
Each of the three buttons has a unique ID so that JavaScript can attach event handlers to them.
- <code>#stato</code> will contain the loading progress messages
  (for example, "In progress...", "OK", or "Error").
- <code>#log</code> will contain the actual text downloaded from the text file.

### ⚙️ The [JavaScript](https://en.wikipedia.org/wiki/JavaScript) logic (<code>app.js</code>)
Let's build the script logic by dividing it into conceptual blocks.

#### Snippet A: Declaring the asynchronous function
```javascript
// Use the 'async' keyword to enable 'await' inside the function
async function caricaLog(nomeFile) {
const elementoStato = document.getElementById('stato');
const elementoLog = document.getElementById('log');
// Loading code...
}
```
:::tip[Explanation]
The `async` keyword tells the browser
that this function will perform asynchronous operations and return a `Promise`.
:::

---

#### Snippet B: The HTTP request with `await fetch()`
```javascript
// 1. Start the error-handling block
try {
    elementoStato.textContent = `Downloading ${nomeFile}...`;
    
    // 2. Send the request and WAIT for the response headers
    const response = await fetch(nomeFile);
    
    // 3. Check whether the file exists on the server (for example, HTTP 200 OK)
    if (!response.ok) {
    throw new Error(`File not found (HTTP status: ${response.status})`);
    }
}
```
:::tip[Explanation]
`await fetch()` pauses execution inside the function
until the server responds, without blocking the web page.
If the file does not exist (for example, `404`),
`response.ok` will be `false`, and we manually generate an error with `throw`.
:::

---
#### Snippet C: Converting to text and updating the DOM
```javascript
// 4. WAIT until the entire file content has been read as text
    const testo = await response.text();
    
    // 5. Update the interface with the received data
    elementoStato.textContent = 'Connection completed successfully.';
    elementoLog.textContent = testo;
    
  } catch (errore) {
    // Handle network problems or missing files
    elementoStato.textContent = 'TRANSMISSION ERROR!';
    elementoLog.textContent = errore.message;
  }
}
```
:::tip[Explanation]
`await response.text()` is needed because the response body
arrives as a stream.
A second `await` completes the text reading process.
:::

---

#### Snippet D: Connecting Event Listeners to the Buttons

```javascript
// Connect the function to the interface buttons
document.getElementById('btn-log1').addEventListener('click', () => caricaLog('log1.txt'));
document.getElementById('btn-log2').addEventListener('click', () => caricaLog('log2.txt'));
document.getElementById('btn-errore').addEventListener('click', () => caricaLog('log-inesistente.txt'));
```

## 🔒 Project Conclusion

<Aside type="note" title="Key Concept Summary" icon="puzzle">
- [Asynchronous execution](https://en.wikipedia.org/wiki/Asynchronous_system): lets the dashboard wait for logs to load without blocking.
- [Promise](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise): represents the future result of a log file request.
- `async` and `await`: allow `caricaLog(nomeFile)` to wait for the response and log content to be read.
- [Fetch API](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API): retrieves `log1.txt` and `log2.txt` from the server.
- [HTTP](https://en.wikipedia.org/wiki/Hypertext_Transfer_Protocol): protocol used to communicate with the local server.
- `response.ok`: detects an unsuccessful HTTP response, such as the test button's `404` error.
- `response.text()`: reads the received log content and returns it as text.
- [DOM](https://en.wikipedia.org/wiki/Document_Object_Model): lets us update `#stato` and `#log` with the loading result and content.
- `try/catch`: handles network errors or unavailable files and displays the message in the dashboard console.
</Aside>
