After trying WebSockets locally, let's see how to use a remote WebSocket server. By publishing `server.js` on a cloud service for persistent **Node.js** processes, such as [**Render**](https://render.com/), the server becomes reachable over the network and browsers can connect to its secure **`wss://`** endpoint—even from workstations that cannot communicate directly over the local network or from outside the classroom.

<AsideTip title="Why use wss:// instead of ws:// in a cloud deployment?">
Cloud services expose a public endpoint over **HTTPS** and **secure WebSocket (`wss://`)**. If a page is loaded over `https://`—or if the server exposes a protected endpoint—the client must use **`wss://`** instead of `ws://localhost:8080`.
</AsideTip>

## Server repository structure

The GitHub repository dedicated to the WebSocket server needs at least the essential files for installing dependencies and starting the process:

<FileTree>
- ws-chat-server/
  - **package.json** Configuration with `"type": "module"` and the `ws` dependency
  - **server.js** WebSocket server listening on `process.env.PORT || 8080`
</FileTree>

## Step-by-step procedure

<Steps>

1. **Adapt the port in `server.js`**

   In a cloud environment, the port is not fixed at `8080`; it is assigned through the `process.env.PORT` environment variable:

   ```javascript
   import { WebSocketServer, WebSocket } from 'ws';

   const PORT = process.env.PORT || 8080;
   const wss = new WebSocketServer({ port: PORT });

   console.log(`WebSocket server listening on port ${PORT}`);
   ```

2. **Publish `package.json` and `server.js` to GitHub**
    Verify that `package.json` contains `"type": "module"` and `ws` in `"dependencies"` (you do not need to upload `node_modules`), then commit and push it to a GitHub repository.

3. **Create a Web Service on Render**
    Sign in to the Render dashboard, click **New +** → **Web Service**, and connect your GitHub repository. Configure:
    * **Build Command**: `npm install`
    * **Start Command**: `node server.js`

4. **Start the deployment and copy the service URL**
    Finish creating the service and wait for the deployment to become active. Render will assign a URL such as `https://your-service-name.onrender.com`.

5. **Update the `wss://` address in `index.html`**
    In the client, replace the local address with the corresponding `wss://` endpoint (without `https://`):

    ```javascript
    const socket = new WebSocket('wss://your-service-name.onrender.com');
    ```

6. Open `index.html` in browsers on several workstations in the lab and send a message to verify real-time broadcasting.

</Steps>
