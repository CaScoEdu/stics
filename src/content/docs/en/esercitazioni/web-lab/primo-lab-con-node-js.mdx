Before building the real-time chat with [**WebSocket**](https://en.wikipedia.org/wiki/WebSocket) and `ws`, it is useful to check that [**Node.js**](https://en.wikipedia.org/wiki/Node.js) works correctly on your computer and see how JavaScript runs on the server rather than inside a browser tab.

<AsideTip title="What is Node.js?">
[**Node.js**](https://en.wikipedia.org/wiki/Node.js) is an open-source runtime environment that lets you run [**JavaScript**](https://en.wikipedia.org/wiki/JavaScript) code outside the browser—for example, on a server or directly on your computer. It is based on Google's [V8](https://en.wikipedia.org/wiki/V8_(JavaScript_engine)) engine and includes built-in modules for working with files, networks, and the operating system.
</AsideTip>

Unlike scripts running in a browser—which interact with the [DOM](https://en.wikipedia.org/wiki/Document_Object_Model) and `window`—a **Node.js** script runs directly in the operating system's runtime and can access built-in modules such as `node:os`.

<AsideTip title="Why start with a minimal Node.js script?">
Running a small script first lets you check your `node` installation, get comfortable with the terminal, and use `"type": "module"` with `import` syntax before handling network connections and events in `server.js`.
</AsideTip>

## Step-by-step instructions

<Steps>

1. **Create the folder and initialize the project**

    Open the terminal in Visual Studio Code and run:

   ```bash
   node -v
   mkdir lab-node-intro
   cd lab-node-intro
   npm init -y
   ```

    <AsideTip title="What does npm init -y do?">
    [**npm**](https://en.wikipedia.org/wiki/Npm_(software)) is the Node.js package manager. The `npm init` command creates the `package.json` file, which contains the project's information and settings. The `-y` option automatically accepts the default values, so you don't have to answer the prompts one by one.
    </AsideTip>

2. **Enable ES modules in `package.json`**

    Make sure `"type": "module"` appears only once in `package.json`. This setting declares that the project uses ES modules, which enables the modern `import` and `export` syntax that you'll use in `app.js` instead of the older `require()` (CommonJS).

    <AsideTip title="What are ES modules?">
    **ES modules (ESM)** are JavaScript's standard system for organizing code into reusable modules. A module can make functions or values available with `export`, which other modules can use with `import`. In **Node.js**, the `"type": "module"` setting enables this syntax in the project's `.js` files.
    </AsideTip>

3. **Create and run `app.js`**
    Create the `app.js` file with the code below:
    
    ```javascript title="app.js"
    import os from 'node:os';

    const username = os.userInfo().username;
    const platform = `${os.platform()} (${os.arch()})`;
    const currentTime = new Date().toLocaleTimeString('it-IT');

    console.log(`Ciao ${username}! Node.js è attivo su ${platform} alle ${currentTime}.`);
    ```

    <AsideTip title="How does app.js work?">
    The script imports `node:os`, a module included with Node.js. `os.userInfo().username` reads the current user's name; `os.platform()` and `os.arch()` return the operating system and architecture, respectively. `new Date().toLocaleTimeString('it-IT')` gets the local time in the Italian format, and `console.log()` prints the message in the terminal.
    </AsideTip>

    Then run it from the terminal:
    ```bash
   node app.js
   ```
    <AsideTip title="The 'node app.js' command">

    `node` is the command that starts the **Node.js** executable, the *runtime* that runs JavaScript outside the browser. When you pass it `app.js`, Node.js loads the file and executes its code; it is not simply an interpreter that reads each instruction one at a time. The **V8** engine analyzes and compiles JavaScript, including during execution (*JIT compilation*), transforming it into machine-executable code.
   </AsideTip>
   

4. You will see text like this in the terminal:
    ```text
    Ciao ilTuoNome! Node.js è attivo su win32 (x64) alle 17:49:10.
    ```

    <AsideTip title="What does the terminal message mean?">
    - **`yourName`**: the name of the user currently signed in to the computer, read from `os.userInfo().username`.
    - **`win32 (x64)`** *(or `linux (x64)` / `darwin (arm64)`)*: the operating system (`os.platform()`, where `win32` identifies Windows, `darwin` macOS, and `linux` Linux) and the processor architecture (`os.arch()`, such as `x64` for 64-bit processors or `arm64` for Apple Silicon/ARM).
    - **`17:49:10`**: the computer's local time when the script runs, formatted according to Italian conventions (`it-IT`).
    </AsideTip>
</Steps>
