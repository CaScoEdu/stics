In practice, when the user clicks the button, the browser executes the [JavaScript](https://en.wikipedia.org/wiki/JavaScript) function that starts `fetch()`. The request is sent to the [server](https://en.wikipedia.org/wiki/Server), which returns a `Response`; the code then reads the content and inserts it into the `DOM`. The key point is that the browser does not freeze: it continues responding to events while waiting for the server response.

## Coding

Below is the contents of the two files:

<Tabs>

<TabItem label="index.html" icon="seti:html" >
```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Async Fetch Introduction</title>
</head>
<body>

    <button onclick="loadMessage()">Load "Hello World"</button>

    <!-- Minimal container where the text is displayed -->
    <div id="output">Waiting for a click...</div>

    <script>
    // 1. 'async' makes the function asynchronous
    async function loadMessage() {
        const output = document.getElementById('output');

        try {
        // 2. 'await fetch' downloads the resource without blocking
        const response = await fetch('hello.txt');

        // 3. Check whether the file was found (e.g. 200 OK)
        if (!response.ok) {
            throw new Error('File not found!');
        }

        // 4. 'await' waits for the response body to be converted to text
        const text = await response.text();

        // 5. Insert the text into the DOM (without alert)
        output.textContent = text;

        } catch (error) {
        // Handle network problems or missing files
        output.textContent = 'Error: ' + error.message;
        }
    }
    </script>

</body>
</html>
```
</TabItem>
<TabItem label="hello.txt" icon="document">
```txt
Hello World!
```
</TabItem>
</Tabs>

In summary, the code uses `async` and `await` to make the request non-blocking:
- `fetch('hello.txt')` starts an [HTTP](https://en.wikipedia.org/wiki/Hypertext_Transfer_Protocol) request,
- `response.ok` verifies that the response was successful,
- and `response.text()` reads the file contents as text.
- The `try/catch` block handles network errors or a missing file, preventing the page from freezing and allowing the [DOM](https://en.wikipedia.org/wiki/Document_Object_Model) to be updated with the result.

## Summary

<KeyConcepts>
- [Asynchronous execution](https://en.wikipedia.org/wiki/Asynchronous_I/O): allows operations such as a network request to be waited on without blocking the interface.
- [Promise](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise): represents the future result of an asynchronous operation.
- `async` and `await`: simplify Promise handling; `await` waits for a result without freezing the browser.
- [Fetch API](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API): enables network requests and receiving a `Response`.
- [HTTP](https://en.wikipedia.org/wiki/Hypertext_Transfer_Protocol): protocol used for communication between browsers and servers.
- `response.ok`: indicates whether the HTTP response has a status from 200 to 299.
- `response.text()`: reads the response body and returns it as text.
- [DOM](https://en.wikipedia.org/wiki/Document_Object_Model): representation of the page that JavaScript can update.
- `try/catch`: handles errors that occur during the request or response reading process.
</KeyConcepts>
