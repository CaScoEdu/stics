### 🕸️ Define the graph with junctions (`grafo.json`)
Now that we've placed the road junctions in `mappa.svg`, we need to update `grafo.json`. Connections will no longer link buildings directly; they will pass through junction nodes.

<Aside type="tip" title="Remember: undirected and weighted graphs">
- **Undirected**: Connections ([edges](https://en.wikipedia.org/wiki/Graph_(discrete_mathematics))) are bidirectional. If junction `A` is connected to junction `B` with a given weight, the same cost applies in both directions.
- **Weighted**: Each edge has a numerical cost (its weight, such as meters or seconds), which **Dijkstra** uses to calculate the shortest route.
</Aside>

Here is a valid `grafo.json` snippet modeling the route from the offices to the intersections through junctions:

```json title="grafo.json"
{
  "edificio-uffici": {
    "snodo-uffici": 30
  },
  "snodo-uffici": {
    "edificio-uffici": 30,
    "snodo-incrocio-ovest": 100
  },
  "snodo-incrocio-ovest": {
    "snodo-uffici": 100,
    "snodo-aule": 100,
    "snodo-mensa": 100
  }
}
```

#### 🔍 How is `grafo.json` structured?
This file represents the campus road and connection graph using a nested `JSON` object (an adjacency map or table):

- **Top-level keys (nodes)**: Each top-level key (such as `"edificio-uffici"` or `"snodo-incrocio-ovest"`) represents a map reference point, whether a building or a strategic intersection.

- **Nested objects (edges and weights)**: Each node contains another object listing its directly reachable neighbors and their numerical weights (the distance in meters or travel cost) required to move between points.

- **Bidirectionality**: Notice that connections are mirrored (for example, from `edificio-uffici` to `snodo-uffici` and vice versa), reflecting an undirected graph where paths can be traveled in either direction.

<Aside type="tip" title="📏 From estimated weights to exact geometric distances">

In the early stages of graph modeling, using fixed approximate values (such as **100** for main routes and **30** for short access paths to buildings) is an **extremely practical and effective choice for teaching**.

##### 💡 Why an approximate approach is "OK" for our purposes:
1. **Focus on the algorithm:** Students can concentrate on how **Dijkstra** works and on the graph data structure (`grafo.json`), without being distracted by repetitive geometric calculations.
2. **Correct relative proportions:** For shortest-route calculations, what matters is not the actual unit of measurement (meters or kilometers), but the **relative cost** of each edge. Giving longer paths a higher weight and access paths a lower one still ensures that the algorithm chooses the right route.

##### 🎯 How to calculate the actual distance in points (pixels)

For complete geometric accuracy, edge weights should exactly match the distance in pixels on the SVG `viewBox` coordinate plane (`0 0 800 600`).

Because paths on our map are **orthogonal** (they run only horizontally or vertically), calculating the distance between nodes A and B is simple and does not require complex formulas such as the Pythagorean theorem:

- **Horizontal movement:** The distance is the absolute difference between the `x` coordinates:  
  `Distance = |x₂ - x₁|`

- **Vertical movement:** The distance is the absolute difference between the `y` coordinates:  
  `Distance = |y₂ - y₁|`

*Example:* If a vertical path starts at `y = 80` and ends at `y = 220`, the exact edge weight in `grafo.json` is simply `|220 - 80| = 140` points.
</Aside>

### ⚙️ Dijkstra's algorithm (`dijkstra.js`)
<Aside type="tip" title="How does Dijkstra work?">
- The algorithm starts at a source node, sets its initial distance to `0`, and sets the distance to every other node to `Infinity (∞)`.
- It progressively explores unvisited neighboring nodes, updating the shortest known path until it reaches the destination.
</Aside>
Separate the algorithm logic by putting it in a dedicated file, `dijkstra.js`:

```javascript title="dijkstra.js"
 /**
 * Dijkstra's algorithm for finding the shortest route in a weighted graph
 */
function calcolaDijkstra(grafo, inizio, fine) {
  if (!grafo || !Object.hasOwn(grafo, inizio) || !Object.hasOwn(grafo, fine)) {
    return [];
  }

  const distanze = {};
  const precedenti = {};
  const nodiNonVisitati = new Set();

  // Initialize distances
  Object.keys(grafo).forEach(nodo => {
    distanze[nodo] = Infinity;
    precedenti[nodo] = null;
    nodiNonVisitati.add(nodo);
  });
  distanze[inizio] = 0;

  while (nodiNonVisitati.size > 0) {
    // Find the unvisited node with the smallest distance
    let nodoCorrente = null;
    nodiNonVisitati.forEach(nodo => {
      if (nodoCorrente === null || distanze[nodo] < distanze[nodoCorrente]) {
        nodoCorrente = nodo;
      }
    });

    if (distanze[nodoCorrente] === Infinity || nodoCorrente === fine) break;

    nodiNonVisitati.delete(nodoCorrente);

    // Update the distances of neighboring nodes
    const vicini = grafo[nodoCorrente] || {};
    for (let vicino in vicini) {
      if (nodiNonVisitati.has(vicino)) {
        let nuovaDistanza = distanze[nodoCorrente] + vicini[vicino];
        if (nuovaDistanza < distanze[vicino]) {
          distanze[vicino] = nuovaDistanza;
          precedenti[vicino] = nodoCorrente;
        }
      }
    }
  }

  // Reconstruct the route in reverse
  const percorso = [];
  let at = fine;
  while (at !== null && at !== undefined) {
    percorso.unshift(at);
    at = precedenti[at];
  }

  return percorso[0] === inizio ? percorso : [];
}
```

    Takes the array of node IDs calculated by Dijkstra, converts each to coordinates using the previous function, and dynamically creates an SVG graphic element as a `<polyline>`. It inserts the element into the DOM (just below the building layer) to show the route on the map.

- `rimuoviSelezioniPrecedenti()`:

    The cleanup (reset) function. Before calculating and showing a new route, it removes highlight CSS classes from previously selected buildings and deletes any previously drawn polyline from the DOM to prevent visual overlaps.

<Aside type="note" title="🐍 The animated dashed-line effect">

The animated dashed-line (or moving-trail) effect uses a CSS technique that manipulates the strokes of an SVG line.

Here's how it works:

1. `stroke-dasharray: 12, 12;`: This property turns a solid line into a regular dashed line, alternating 12-pixel strokes and 12-pixel gaps (for a total pattern length of 24 pixels).

2. `stroke-dashoffset`: This property determines the starting point of the dash pattern along the line.

3. The `@keyframes` animation: by continuously and linearly (`infinite`) changing `stroke-dashoffset` from `24` to `0`, the dashes move forward along the route.

To the human eye, this continuous motion creates the familiar illusion of a moving flow (like "marching ants" or a navigation route animation).
</Aside>

<Aside type="note" title="Key concepts summary" icon="puzzle">
- [`grafo.json`](https://en.wikipedia.org/wiki/Graph_(discrete_mathematics)): represents the campus network with nodes and weighted edges; weights indicate distances or travel costs.
- [Dijkstra's algorithm](https://en.wikipedia.org/wiki/Dijkstra%27s_algorithm): finds the shortest route between a start and destination in a graph with non-negative weights.
- [`dijkstra.js`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules): contains the shortest-route algorithm, separate from the interface logic.
- [`fetch()`](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch) and [`async` / `await`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/async_function): asynchronously load `grafo.json` before the route is calculated.
- [SVG coordinates](https://developer.mozilla.org/en-US/docs/Web/SVG/Attribute): the `cx`, `cy`, `x`, and `y` attributes provide node positions on the map.
- [`<polyline>`](https://developer.mozilla.org/en-US/docs/Web/SVG/Element/polyline) and [CSS animations](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_animations/Using_CSS_animations): draw and animate the route's dashed line.
- [`classList`](https://developer.mozilla.org/en-US/docs/Web/API/Element/classList): adds or removes highlighting classes for the start and destination.
