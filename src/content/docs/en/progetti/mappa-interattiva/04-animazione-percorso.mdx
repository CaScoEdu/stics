### 🕸️ Define the Graph with Nodes (`grafo.json`)
Now that we have positioned the road nodes in `mappa.svg`, update `grafo.json`. Connections will no longer join buildings directly, but will pass through node points.

<Aside type="tip" title="Review: Unweighted vs. Weighted Undirected Graphs">
- **Undirected**: The connections ([edges](https://en.wikipedia.org/wiki/Graph_(discrete_mathematics))) are bidirectional. If node `A` is connected to node `B` with a given weight, the same route applies in both directions.
- **Weighted**: Every edge has a numerical cost (the weight, such as meters or seconds), used by **Dijkstra** to calculate the shortest route.
</Aside>

Here is a valid `grafo.json` excerpt that models the route from the offices to intersections through the nodes:

```json title="grafo.json"
{
  "edificio-uffici": {
    "snodo-uffici": 30
  },
  "snodo-uffici": {
    "edificio-uffici": 30,
    "snodo-incrocio-ovest": 100
  },
  "snodo-incrocio-ovest": {
    "snodo-uffici": 100,
    "snodo-aule": 100,
    "snodo-mensa": 100
  }
}
```

#### 🔍 How is `grafo.json` structured?
This file represents the campus road and connection graph using a nested `JSON` object (a map or adjacency table):

- **Primary keys (nodes)**: Each top-level key (such as `"edificio-uffici"` or `"snodo-incrocio-ovest"`) represents a map reference point, whether a building or a strategic intersection.

- **Nested objects (edges and weights)**: Inside each node, another object lists directly reachable neighbors and provides a numerical weight (distance in meters or travel cost) for moving between points.

- **Bidirectionality**: Connections are mirrored (for example, from `edificio-uffici` to `snodo-uffici` and back), respecting the undirected graph model in which roads are usable in both directions.

<Aside type="tip" title="📏 From estimated weights to exact geometric distance">

During the first stages of graph modeling, using fixed approximate values (such as **100** for main roads and **30** for short access connections to locations) is an **extremely practical and effective choice for educational purposes**.

##### 💡 Perché l'approccio approssimativo è "OK" per i nostri fini:
1. **Focus sull'algoritmo:** Permette agli studenti di concentrarsi sulla logica di funzionamento di **Dijkstra** e sulla struttura dati del grafo (`grafo.json`), senza il rischio di distrarsi con calcoli geometrici ripetitivi.
2. **Proporzione logica corretta:** Ai fini del calcolo del percorso minimo, ciò che conta davvero non è l'unità di misura reale (metri o chilometri), ma la **relazione di costo** tra i vari archi. Assegnare un peso maggiore alle strade lunghe e uno minore ai vialetti di accesso garantisce che l'algoritmo scelga comunque la strada corretta.

##### 🎯 Come calcolare la distanza reale in punti (pixel)

Per un rigore geometrico assoluto, i pesi degli archi dovrebbero corrispondere esattamente alla distanza in pixel sul piano cartesiano del `viewBox` dell'SVG (`0 0 800 600`). 

Poiché nella nostra mappa i percorsi stradali sono **ortogonali** (cioè si muovono esclusivamente in orizzontale o in verticale), il calcolo della distanza tra due nodi A e B è estremamente semplice e non richiede formule complesse come il teorema di Pitagora:

- **Spostamento orizzontale:** La distanza corrisponde alla differenza delle coordinate `x` in valore assoluto:  
  `Distanza = |x₂ - x₁|`

- **Spostamento verticale:** La distanza corrisponde alla differenza delle coordinate `y` in valore assoluto:  
  `Distanza = |y₂ - y₁|`

*Esempio pratico:* Se un tratto di strada verticale parte dal punto `y = 80` e arriva a `y = 220`, il peso esatto dell'arco nel file `grafo.json` sarà semplicemente `|220 - 80| = 140` punti.
</Aside>

### ⚙️ Dijkstra's Algorithm (`dijkstra.js`)
<Aside type="tip" title="How does Dijkstra's algorithm work?">
- The algorithm starts from an origin node and sets the distance to that node to `0`, and the distance to every other node to `Infinity (∞)`.
- It progressively explores unvisited neighboring nodes, updating the shortest recorded path until it reaches the destination node.
</Aside>
Separate the algorithmic logic into a dedicated file, `dijkstra.js`:

```javascript title="dijkstra.js"
 /**
 * Algoritmo di Dijkstra per trovare il percorso minimo su un grafo pesato
 */
function calcolaDijkstra(grafo, inizio, fine) {
  if (!grafo || !Object.hasOwn(grafo, inizio) || !Object.hasOwn(grafo, fine)) {
    return [];
  }

  const distanze = {};
  const precedenti = {};
  const nodiNonVisitati = new Set();

  // Inizializzazione delle distanze
  Object.keys(grafo).forEach(nodo => {
    distanze[nodo] = Infinity;
    precedenti[nodo] = null;
    nodiNonVisitati.add(nodo);
  });
  distanze[inizio] = 0;

  while (nodiNonVisitati.size > 0) {
    // Trova il nodo non visitato con la distanza minore
    let nodoCorrente = null;
    nodiNonVisitati.forEach(nodo => {
      if (nodoCorrente === null || distanze[nodo] < distanze[nodoCorrente]) {
        nodoCorrente = nodo;
      }
    });

    if (distanze[nodoCorrente] === Infinity || nodoCorrente === fine) break;

    nodiNonVisitati.delete(nodoCorrente);

    // Aggiorna le distanze dei vicini
    const vicini = grafo[nodoCorrente] || {};
    for (let vicino in vicini) {
      if (nodiNonVisitati.has(vicino)) {
        let nuovaDistanza = distanze[nodoCorrente] + vicini[vicino];
        if (nuovaDistanza < distanze[vicino]) {
          distanze[vicino] = nuovaDistanza;
          precedenti[vicino] = nodoCorrente;
        }
      }
    }
  }

  // Ricostruzione del percorso a ritroso
  const percorso = [];
  let at = fine;
  while (at !== null && at !== undefined) {
    percorso.unshift(at);
    at = precedenti[at];
  }

  return percorso[0] === inizio ? percorso : [];
}
```

<Aside type="note" title="🐍 The animated route-line effect">

The "snake" effect (or moving-trail effect) is created using a clever technique that manipulates the dashes of an SVG line through CSS.

Here is how it works:

1. `stroke-dasharray: 12, 12;`: This property turns a continuous line into a regular dashed pattern, alternating 12-pixel solid segments and 12-pixel gaps (for a total pattern length of 24 pixels).

2. `stroke-dashoffset`: This property determines the starting position of the dash pattern along the line.

3. The `@keyframes` animation: cycling `stroke-dashoffset` continuously from `24` to `0` with linear timing and `infinite` repetition makes the dashes move forward along the route.

To the human eye, this continuous dash movement creates the characteristic optical illusion of flowing motion (similar to an ant trail or an animated navigation route).
</Aside>
