- definisci una convenzione di pesi che resti coerente in tutto il progetto: brevi tratti di accesso = peso basso, dorsali principali = peso più alto;

Queste piccole scelte migliorano molto la leggibilità del progetto, riducono i bug e aiutano la fase di debugging.
</Aside>

### 🎯 Obiettivo della lezione

In questa lezione trasformiamo la mappa da una semplice rappresentazione grafica a una vera rete di spostamenti: i locali diventano nodi del [grafo](https://it.wikipedia.org/wiki/Grafo), i percorsi pedonali diventano archi pesati e il browser calcola automaticamente il tragitto più corto tra due punti con l'[algoritmo di Dijkstra](https://it.wikipedia.org/wiki/Algoritmo_di_Dijkstra). L'output finale è una navigazione interattiva, con evidenziazione dei locali e una linea animata che segue il percorso scelto.

<Aside type="note" title="Risultato atteso">
Al termine della lezione avrai un'applicazione in cui, selezionando partenza e destinazione, il sistema:
- legge il grafo dal file JSON,
- applica Dijkstra per trovare il percorso minimo,
- disegna la poligonale sulla mappa,
- evidenzia gli edifici coinvolti e mostra la serpentina animata.
</Aside>

### 🕸️ Definizione del Grafo con gli Snodi (`grafo.json`)
Ora che abbiamo posizionato gli snodi stradali in `mappa.svg`, dobbiamo aggiornare il file `grafo.json`. I collegamenti non uniranno più direttamente gli edifici, ma passeranno attraverso i nodi di snodo.

<Aside type="tip" title="Ricordiamo i concetti di Grafo Non Orientato e Pesato">
- **Non orientato**: I collegamenti ([archi](https://it.wikipedia.org/wiki/Grafo)) sono bidirezionali. Se lo snodo `A` è collegato allo snodo `B` con un certo peso, la stessa percorrenza vale in entrambi i
versi.
- **Pesato**: Ogni arco ha un costo numerico (il peso, es. metri o secondi), utilizzato da **Dijkstra** per calcolare il percorso minimo.
</Aside>

Ecco un frammento corretto di grafo.json che modella il passaggio dagli uffici agli incroci tramite gli snodi:

```json title="grafo.json"
{
  "edificio-uffici": {
    "snodo-uffici": 30
  },
  "snodo-uffici": {
    "edificio-uffici": 30,
    "snodo-incrocio-ovest": 100
  },
  "snodo-incrocio-ovest": {
    "snodo-uffici": 100,
    "snodo-aule": 100,
    "snodo-mensa": 100
  }
}
```

#### 🔍 Come è strutturato `grafo.json`?
Questo file rappresenta il grafo stradale e di collegamento del campus utilizzando un oggetto `JSON` nidificato (una mappa o tabella di adiacenza):

- **Chiavi principali (nodi)**: Ogni chiave di primo livello (come `"edificio-uffici"` o `"snodo-incrocio-ovest"`) rappresenta un punto di riferimento della mappa, sia esso un edificio o un incrocio strategico.

- **Oggetti interni (archi e pesi)**: All'interno di ogni nodo troviamo un ulteriore oggetto che elenca i vicini direttamente raggiungibili e, come valore numerico, il peso (la distanza in metri o il costo di percorrenza) necessario per spostarsi da un punto all'altro.

- **Bidirezionalità**: Noterai che i collegamenti sono speculari (es. da `edificio-uffici` a `snodo-uffici` e viceversa), rispettando la natura di grafo non orientato in cui le strade sono percorribili in entrambi i sensi.

<Aside type="tip" title="📏 Dal peso stimato alla distanza geometrica esatta">

Nelle prime fasi di modellazione di un grafo, l'utilizzo di valori fissi e approssimativi (come **100** per le dorsali principali e **30** per i brevi raccordi di uscita verso i locali) è una scelta **estremamente pragmatica ed efficace per fini didattici**. 

##### 💡 Perché l'approccio approssimativo è "OK" per i nostri fini:
1. **Focus sull'algoritmo:** Permette agli studenti di concentrarsi sulla logica di funzionamento di **Dijkstra** e sulla struttura dati del grafo (`grafo.json`), senza il rischio di distrarsi con calcoli geometrici ripetitivi.
2. **Proporzione logica corretta:** Ai fini del calcolo del percorso minimo, ciò che conta davvero non è l'unità di misura reale (metri o chilometri), ma la **relazione di costo** tra i vari archi. Assegnare un peso maggiore alle strade lunghe e uno minore ai vialetti di accesso garantisce che l'algoritmo scelga comunque la strada corretta.

##### 🎯 Come calcolare la distanza reale in punti (pixel)

Per un rigore geometrico assoluto, i pesi degli archi dovrebbero corrispondere esattamente alla distanza in pixel sul piano cartesiano del `viewBox` dell'SVG (`0 0 800 600`). 

Poiché nella nostra mappa i percorsi stradali sono **ortogonali** (cioè si muovono esclusivamente in orizzontale o in verticale), il calcolo della distanza tra due nodi A e B è estremamente semplice e non richiede formule complesse come il teorema di Pitagora:

- **Spostamento orizzontale:** La distanza corrisponde alla differenza delle coordinate `x` in valore assoluto:  
  `Distanza = |x₂ - x₁|`

- **Spostamento verticale:** La distanza corrisponde alla differenza delle coordinate `y` in valore assoluto:  
  `Distanza = |y₂ - y₁|`

*Esempio pratico:* Se un tratto di strada verticale parte dal punto `y = 80` e arriva a `y = 220`, il peso esatto dell'arco nel file `grafo.json` sarà semplicemente `|220 - 80| = 140` punti.
</Aside>

### ⚙️ L'Algoritmo di Dijkstra (`dijkstra.js`)
<Aside type="tip" title="Come funziona Dijkstra?">
- L'algoritmo parte da un nodo di origine e imposta la distanza iniziale verso di esso a `0`, e verso tutti gli altri nodi a `Infinito (∞)`. 
- Esplora progressivamente i nodi vicini non ancora visitati, aggiornando il cammino più breve registrato fino a raggiungere il nodo di destinazione.
</Aside>
Separiamo la logica algoritmica creandola all'interno di un file dedicato, `dijkstra.js`:

```javascript title="dijkstra.js"
 /**
 * Algoritmo di Dijkstra per trovare il percorso minimo su un grafo pesato
 */
function calcolaDijkstra(grafo, inizio, fine) {
  if (!grafo || !Object.hasOwn(grafo, inizio) || !Object.hasOwn(grafo, fine)) {
    return [];
  }

  const distanze = {};
  const precedenti = {};
  const nodiNonVisitati = new Set();

  // Inizializzazione delle distanze
  Object.keys(grafo).forEach(nodo => {
    distanze[nodo] = Infinity;
    precedenti[nodo] = null;
    nodiNonVisitati.add(nodo);
  });
  distanze[inizio] = 0;

  while (nodiNonVisitati.size > 0) {
    // Trova il nodo non visitato con la distanza minore
    let nodoCorrente = null;
    nodiNonVisitati.forEach(nodo => {
      if (nodoCorrente === null || distanze[nodo] < distanze[nodoCorrente]) {
        nodoCorrente = nodo;
      }
    });

    if (distanze[nodoCorrente] === Infinity || nodoCorrente === fine) break;

    nodiNonVisitati.delete(nodoCorrente);

    // Aggiorna le distanze dei vicini
    const vicini = grafo[nodoCorrente] || {};
    for (let vicino in vicini) {
      if (nodiNonVisitati.has(vicino)) {
        let nuovaDistanza = distanze[nodoCorrente] + vicini[vicino];
        if (nuovaDistanza < distanze[vicino]) {
          distanze[vicino] = nuovaDistanza;
          precedenti[vicino] = nodoCorrente;
        }
      }
    }
  }

  // Ricostruzione del percorso a ritroso
  const percorso = [];
  let at = fine;
  while (at !== null && at !== undefined) {
    percorso.unshift(at);
    at = precedenti[at];
  }

  return percorso[0] === inizio ? percorso : [];
}
```

<Aside type="note" title="🐍 l'effetto serpentina">

L'effetto "serpentina" (o effetto scia in movimento) si ottiene sfruttando una tecnica intelligente basata sulla manipolazione dei tratti di una linea SVG tramite CSS.

Ecco come funziona in sintesi:

1. `stroke-dasharray: 12, 12;`: Questa proprietà trasforma una linea continua in un tratteggio regolare, alternando segmenti pieni di 12 pixel e spazi vuoti di 12 pixel (per una lunghezza totale del pattern pari a 24 pixel).

2. `stroke-dashoffset`: Questa proprietà determina il punto di partenza da cui inizia il tratteggio lungo la linea.

3. L'animazione `@keyframes`: facendo scorrere ciclicamente il valore di `stroke-dashoffset` da `24` fino a `0` in modo lineare e continuo (`infinite`), i trattini si spostano in avanti lungo tutto il percorso.

All'occhio umano, questo scorrimento continuo dei trattini crea la tipica illusione ottica di un flusso in movimento (stile "marcia delle formiche" o percorso animato del navigatore).
</Aside>
